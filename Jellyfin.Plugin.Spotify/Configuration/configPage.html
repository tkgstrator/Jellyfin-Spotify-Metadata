Spotify API

The selected source is used exclusively; there is no automatic fallback. Web Player is experimental. Lookup by a known ID works anonymously, but search is unavailable because session bootstrap depends on Spotify's unsupported internal API.
Create an app in the Spotify Developer Dashboard. The plugin uses the client credentials flow: no listener signs in, and no refresh token or Spotify account data is stored. Credentials stay in Jellyfin's plugin configuration and are never sent anywhere but Spotify.

Catalog

ISO country code used for availability and track relinking. Spotify ids are global, so this does not scope the saved id.

Requests are sent one at a time, at least this far apart. Raise the interval if the log reports rate limiting.

Cache

Stores responses on disk so the same track, album or artist is not looked up twice. Strongly recommended: a library scan would otherwise repeat the same album query once per track.
Kept shorter than the cache lifetime, since a track missing today may be added to the catalog tomorrow.
Upper bound on the memory the cache may use. Least recently used entries are dropped once it is reached, so a large library cannot grow it without limit.
Responses above this size stay in memory only. Search responses run to about 31 KB and are rarely repeated once an id is known, whereas id lookups are around 1.5 KB and repeat often — the default of 8 KB keeps the useful ones on disk and the bulky ones off it.
